# Flashcard Metadata + Tag Filter + Scoring Overhaul

**Date:** 2026-08-27
**Status:** Implemented

## Context

The YouTube Vocabulary Deck was limited to 50 items with scoring that prioritized frequent (common) words. The system needed to:
1. Extract up to 150 items (more vocabulary per video)
2. Prioritize unusual, extravagant words over common ones
3. Add metadata to each flashcard for classification
4. Show tags in the editor and allow filtering by tag

## Design Decisions

### Generic Metadata (not language-coupled)

The flashcard system is a **generic pair memorizer** — not just for languages. Metadata must support any domain (vehicles, dog breeds, people, etc.). The schema uses `tags: string[]` instead of domain-specific fields.

```typescript
interface FlashcardMetadata {
  difficulty: 'basic' | 'intermediate' | 'advanced';
  frequencyRank: number;
  audioTimestamp?: number;
  tags: string[];
}
```

- `difficulty`: always present, derived heuristically from word length + type
- `frequencyRank`: position 1-150 in the scoring order
- `audioTimestamp`: seconds in video, for YouTube decks only
- `tags`: array of strings — auto-generated by NLP, user-editable

### Scoring Inversion

The old scoring rewarded frequent words (common). The new scoring **rewards rare + complex words**:

| Signal | Effect | Rationale |
|--------|--------|-----------|
| Low frequency (1-2 in video) | +3.0 / +2.0 | Rare in content = more interesting to learn |
| High frequency (10+) | -1.0 | Likely common words |
| Long words (6+ chars) | +1.5 | More complex vocabulary |
| Short words (2-3 chars) | -0.5 / -1.0 | Likely simple |
| Phrasal verbs | +1.5 | High learning value |
| Common expressions | +1.0 | Useful patterns |
| Generic blacklist words | -3.0 | Boring everyday words |

### Tag Filter (UI)

Instead of multiple views/accordions, a simpler approach:
- **Column "Tags"** in the existing card table with colored badges
- **Filter bar** above the table with clickable tag chips
- Click a tag → filter table to only cards with that tag
- Click "All" → show everything

## Metadata Generation (NLP)

The ranker generates metadata for each item after scoring:

```
difficulty heuristic:
  - basic: common expressions, short words, high frequency
  - intermediate: phrasal verbs, collocations, medium words
  - advanced: long words (7+ chars), low frequency, complex expressions

tags derived from:
  - phrase.category → "phrasal_verb", "expression", "collocation"
  - word POS → "noun", "verb", "adj", "adv"
  - difficulty → "basic", "intermediate", "advanced"
```

## No Backend API Changes

The Cloud Function contract is unchanged: `{ userId, cards, targetLang, sourceLang }` → `{ translations, consumedChars, userRemainingChars }`. Metadata flows through the existing `cards[]` array as an additional field on each card.
