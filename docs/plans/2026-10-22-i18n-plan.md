# Plan: i18n base — one language per screen, then a switcher (U-13)

**Date:** 2026-10-22
**Status:** Planned (not started). Elevated with U-13 from P2 to P1: this is the
prerequisite for every locale (`usability-gaps.md` §8 order 5) and for the `en`
rollout gate (`market-positioning.md` §5, Phases 2/5).
**Scope:** the UI's own language. Content languages (~25 voice languages,
`translationService`, YouTube deck targets) are untouched.

## 3. Decisions

- **Library:** `react-i18next` + `i18next` (industry default, lazy namespace
  loading, React 19 compatible). No other candidate is evaluated in this plan;
  reconsider only if install fails.
- **`es` is the source of truth first** (P1–P3 land a single neutral-ES locale);
  `en` is a translation pass over the finished key set (P5), never before.
- **Extraction granularity:** one namespace per feature area
  (`common`, `nav`, `auth`, `dashboard`, `game`, `editor`, `store`, `onboarding`,
  `settings`, `errors`) so PRs stay reviewable.
- **Out of scope:** `error.message` → friendly copy mapping beyond the toast
  layer (tracked as U-11, `P2/2026-10-16-error-message-crudo-en-cliente.md`;
  P3 here only routes toasts through the i18n layer so U-11 can land on top);
  localized legal pages, decks, pricing (I-6..I-8 — `BUSINESS_MODEL.md` owns
  pricing); `hreflang`/sitemap (I-9 — SEO phase).

## 4. Phases

Estimates in hours of agent-executed work with human review; they assume the
gates below run green at each phase boundary.

### P0 — String inventory (2 h)
- [ ] P0-1 `grep` every user-facing literal: JSX text nodes, `toast`/`showToast`
      strings, `placeholder`, `aria-label`, `title`, `alt`, auth messages,
      navbar labels, `document.title`.
- [ ] P0-2 Produce `src/i18n/INVENTORY.md` (or plan appendix): file:line → key
      proposal → language of origin (ES-neutral / AR / EN). This is the
      checklist every later phase burns down.
- [ ] P0-3 Freeze rule: no new user-facing literals in `src/` after this point;
      new strings go straight to the `es` catalogue (AGENTS §24/§4 style).

**Gate:** inventory covers every `grep -rnE "showToast\(|toast\(|placeholder=|aria-label="`
hit in `src/`.

### P1 — Neutral ES quick win, no library yet (6 h)
- [ ] P1-1 Delete/replace the 4 English navbar labels
      (`Navbar.tsx:20,25,30,35` → Panel, Actividad, Reportes, Ajustes).
- [ ] P1-2 Replace the 4 `Loading...`/`Loading deck...` strings with neutral ES.
- [ ] P1-3 De-vose the 4 onboarding strings (`CustomCreationSection.tsx`,
      `DeckStoreOnboarding.tsx`) and align `docs/ONBOARDING-UX-DESIGN.md`.
- [ ] P1-4 Translate the 7 English auth messages in `AuthContext.tsx:99-116`
      (maps to key space later; for now plain ES).
- [ ] P1-5 Sweep remaining EN literals found in P0 (`LandingPage` footer links,
      `GuestBanner` if any EN remains, buttons `Save`/`Cancel`/`Delete`).

**Gate:** `grep -rnE "Loading\.\.\.|label: '(Dashboard|History|Reports|Settings)'|Preferís|Creá|Explorá|'Login failed"` returns nothing in `src/`;
`npx tsc --noEmit` empty; `npx vitest run tests/` green (tests asserting those
strings — e.g. `screen.getByText('Loading...')` — updated per §37).

### P2 — Install and wire the library (4 h)
- [ ] P2-1 Install `i18next` + `react-i18next`; create `src/i18n/index.ts`
      (init with `lng: 'es'`, `supportedLngs: ['es']`, `resources: { es: {...} }`,
      `compatibilityJSON: 'v4'` for `Intl` plural handling) and import it in
      `src/main.tsx`.
- [ ] P2-2 Create the namespace skeletons (`src/i18n/es/{common,nav,auth,...}.ts`)
      typed as `Record<string, string>`; `src/i18n/types.ts` exports a
      `TranslationKey` union derived from them so keys are compile-checked.
- [ ] P2-3 Add the test helper: `tests/helpers/i18n.ts` wrapping `render` with
      the same provider, so component tests keep working.

**Gate:** a smoke test renders one component through `t()` and asserts the ES
string; `tsc --noEmit` empty.

### P3 — Extraction to `es` (16 h, phased by namespace)
- [ ] P3-1 Extract in this order (dependency-free first): `common` → `nav` →
      `auth` → `errors` (toast strings from `useAppHandlers`, `useListEditorActions`)
      → `dashboard` → `editor` → `store` → `onboarding` → `settings` → `game`.
- [ ] P3-2 Toast layer: every `showToast('...')` literal becomes
      `showToast(t('area.key'), ...)`; parameters via `t('k', { count })`.
- [ ] P3-3 `document.title` / `meta` strings stay static for now (SEO phase
      owns per-route meta); record them in the inventory as deferred.
- [ ] P3-4 Update tests that assert literal strings to use the ES catalogue
      value (§37); keep the `tests/helpers/i18n.ts` wrapper as the single
      entry point.

**Gate per namespace:** grep shows no user-facing literals left in the files of
that namespace; the suite stays green after each namespace, not at the end.

**Gate final (P3):** `npx tsc --noEmit` empty; `npx vitest run tests/` green;
`grep -rnE "showToast\('[A-Z]" src/` empty; inventory checklist 100% burned down.

### P4 — Locale detection + switcher + dynamic `lang` (8 h)
- [ ] P4-1 Persisted preference: `localStorage` key + `navigator.language`
      fallback on first visit; `i18n.changeLanguage` on switch.
- [ ] P4-2 Switcher component (accessible `<select>`/`button` group with
      `aria-label`, per AGENTS §21) placed in Settings and Navbar; guest-safe
      (localStorage, no quota/quota-service coupling, §31: no Cloud Function).
- [ ] P4-3 `useEffect` syncing `document.documentElement.lang` with
      `i18n.language` (replaces the hard-coded `src/index.html:3` value on
      mount; the attribute stays `es` as SSR-free default).
- [ ] P4-4 `supportedLngs` gains `en` only in P5 — the switcher renders
      disabled/hidden for unsupported locales so P4 ships without `en`.

**Gate:** unit test asserts `lang` attribute follows `changeLanguage`; switcher
keyboard-accessible test; `tsc` + suite green.

### P5 — Full `en` locale (12 h)
- [ ] P5-1 Translate the finished key set (P3 output) into
      `src/i18n/en/*.ts` — adaptation, not literal translation (I-5 rule).
- [ ] P5-2 Enable `en` in `supportedLngs`; switcher lists both.
- [ ] P5-3 Parity check: a test (or lint script) asserts `en` and `es` key sets
      are identical — missing keys fail CI.

**Gate:** key-parity test green; spot-check of every namespace in `en`;
`tsc` + suite green.

### P6 — Verification and documentation (4 h)
- [ ] P6-1 Full gates: `npx tsc --noEmit`, `npx vitest run tests/`,
      `npx playwright test` (if E2E fixtures asserted the old strings —
      `e2e/` has none today, verified), `npm run test:backend` (untouched, run
      for safety).
- [ ] P6-2 `grep` audit repeated from P0 — zero hits for EN/AR leftovers.
- [ ] P6-3 Update `docs/dashboard-api-trigger-analysis.md` change log (no API
      change; §33 requires the row because `useAppHandlers.ts` is touched), the
      U-13 issue (resolved row → `done/`), roadmap + usability-gaps rows, README
      counts.

**Total: ~52 h**

## 5. Risks

| Risk | Mitigation |
|---|---|
| Extraction touches 97 components → huge diff | namespace-by-namespace with a green gate after each (P3 rule) |
| Tests break en masse on string change | single `tests/helpers/i18n.ts` wrapper + assert via catalogue keys (§37) |
| Switcher adds a global state that fights the store | language lives in i18next only; no `gameStore` field |
| `en` ships half-translated | key-parity test in P5-2 blocks it |

## 6. Explicit non-goals

- No per-route SEO meta (Phase 3 of the market plan).
- No localized decks, legal pages, or pricing (I-6..I-8; pricing decision
  belongs to `docs/BUSINESS_MODEL.md` per AGENTS §44).
- No `hreflang`/sitemap (I-9, depends on I-1..I-4 + SEO phase).
- No `pt-BR`/`fr`/`de`/`ja` (market plan Phase 5), but P2's `supportedLngs` and
  P5's parity test make them additive.
