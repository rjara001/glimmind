## 4. Sign-up and first-run flow

1. Signed out → `/` (`LandingPage`) → "Empezar gratis" → `/login`; upgrade → `/login?next=/settings`.
2. `/login` (`src/components/Auth.tsx:20-61`): Google via `signInWithPopup`, COOP/cancelation errors fall back to `signInWithRedirect`. "Continue as guest" → `handleLoginDev` (`src/App.tsx:48-57`) injects `{ uid: GUEST_ID, displayName: 'Local Guest' }` into `AuthContext` and `gameStore`.
3. Session restore: `src/context/AuthContext.tsx:53-77` and `src/hooks/app/useAppBootstrap.ts:35-60` read `glimmind_guest_user` from `localStorage`; signing in with Google removes that key (`AuthContext.tsx:55`).
4. Bootstrap: `useAppBootstrap` subscribes `onAuthStateChanged`, calls `loadInitialData()`, flushes sync on `beforeunload` / `pagehide` / `visibilitychange`, and auto-navigates to `/game` when `glimmind_last_played` exists.
5. First run: `isFirstTime = lists.length === 0` → `DeckStoreOnboarding` (`Dashboard.tsx:154-164`): catalogue → preview → `useDeckValidation` → import → `onCreateAndPlay`. Alternative: `CustomCreationSection` → empty editor.
6. **No email/password registration UI.** `AuthContext.login` exists but no component calls it. Entry is Google or guest only.

**Risk:** guest data is localStorage-only. `docs/issues/P1/2026-10-13-guest-decks-erased-on-user-switch.md` records that signing in after a guest session erases the guest's decks.

## 7. Access control defect (newly filed)

```
src/context/AuthContext.tsx:33-38   mapFirebaseUser → { uid, displayName, email, photoURL }   // no `role`
src/components/ProtectedRoute.tsx:46 const userRole = user.role || 'user'
src/components/ProtectedRoute.tsx:48 return <Navigate to="/403" replace />
src/App.tsx:366                     <Route path="*" element={<Navigate to="/dashboard" replace />} />
```

`role` is never assigned anywhere in `src/`. Every user resolves to `'user'`, so `/admin` (`src/App.tsx:356`, `allowedRoles: ['owner','admin']`) always navigates to `/403`, a route that does not exist, so the catch-all silently bounces the visitor to `/dashboard`.
Filed as `docs/issues/P2/2026-10-20-admin-inalcanzable-por-role.md`.

### 8.1 Runtime third-party dependencies in production

`dist/index.html` (1773 bytes) ships, after the build:

```html
<script src="https://cdn.tailwindcss.com"></script>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700;900&display=swap" rel="stylesheet">
<script type="importmap"> { "react": "https://esm.sh/react@19.0.0", ... "next": "https://esm.sh/next@^16.1.6" } </script>
```

- `tailwindcss`, `postcss` and any `tailwind.config.*` are **absent from the project entirely**. Every Tailwind utility class in the app is therefore styled by the browser-side CDN JIT at runtime. There is no compiled Tailwind output in `assets/index-kzs72_o6.css`.
- The importmap resolves `react`, `react-dom`, `firebase/*`, `next` and `@google/genai` to `esm.sh`. `next` appears in `dependencies` with **0 imports** in `src/`.
- Impact: a CDN outage, a corporate proxy block or an ad-blocker rule breaks rendering for every user, with no build-time detection. Filed as `docs/issues/P1/2026-10-20-tailwind-cdn-en-runtime-produccion.md`.

## 12. Summary

**Solid:** game engine, tier architecture, Stripe live with runbook, premium voice gating, E2E gate, client error pipeline, maintained issue index.

**Blocking for an international launch:** no i18n, no SEO surface, marketing copy that promises features which do not exist, sync that does not sync, and a production build whose styling depends on a browser-CDN script.

**Blocking for usability:** 8 open P1 issues, quota invisible until a 429, raw English errors in a Spanish UI, no deck-load error state in `GameView`.
